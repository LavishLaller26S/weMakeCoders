# WeMakeCoder home-page UI

UI only, following the Miro Main UI, Add Question, Create Group, and Join Group frames. No backend Java, configuration, or API logic is changed.

## Run the frontend

The files are in `frontend/` inside your WeMakeCoder project. Node.js 18 or newer is required. There are no packages to install.

```sh
cd /Users/lavish/Lavish/weMakeCoders/WeMakeCoder/frontend
npm start
```

Open `http://localhost:5173`. Run your backend separately as usual. The frontend server forwards the existing `/wmc/api/*` and `/wmd/api/*` requests to `http://localhost:8080` by default. It preserves request payloads, response bodies, and backend HTTP statuses. No backend changes are needed for this frontend proxy.

If your backend runs on another address:

```sh
BACKEND_URL=http://localhost:8081 npm start
```

To change the frontend port, use `PORT=5174 npm start`.

1. Keep the UI API base URL set to `http://localhost:5173` to use the frontend proxy.
2. Enter an existing user's UUID. Registration/login/logout are not part of this UI.
3. Keep DSA path ID as `1`, or enter another value to test the current route. That GET route declares an entry ID but its service reads the full user list.
4. Click **Load home page**.
5. Use **Add Question**, select rows and **Delete**, or **Create Group** / **Join Group**.

Each section and modal shows its exact API. **API activity** shows method, full URL, HTTP status, timing, request body, and response body. Passwords are sent to the backend but masked in the activity panel and export. Add observations to requests and export the activity as JSON for later test/progress tracking.

## Current API mapping

User routes retain `/wmc/api/v1/users/{userId}`; group routes retain `/wmd/api/v1/user/{userId}` exactly as declared in your controllers.

- Profile, personal question list, add, delete, joined groups, create, join, and name availability are mapped.
- Name availability treats an **empty 404** as available; other 404 responses remain errors.
- DSA source values are `LEETCODE`, `CODEFORCES`, `CODECHEF`, `OTHER`.
- Submitted At is generated by the backend; the modal displays this rather than sending an unsupported date field.
- Create Group includes `displayName`, which the current API accepts.
- Join Group includes Group ID because the current API requires it in addition to code/password.
- Add Question allows optional multiple groups and additional manually entered group IDs for testing.
- Delete sends a raw numeric ID array, with a confirmation dialog.
- Update, account edits, group question-bank navigation, active counts, and login/logout are not simulated. The UI marks unavailable actions instead of inventing an API or data.

Forms preserve user input after API errors. They do not impose extra field validation beyond connection configuration, so empty values and invalid body IDs can reach the backend for testing. API base/user/path settings are stored locally; request history and observations remain in memory until exported. There are no automatic mutation retries and no live sample rows.

## Standalone preview

You can serve this folder with a static file server to inspect the layout, but `npm start` includes the API proxy for live testing. If you set the UI base URL directly to a different backend origin, that backend must allow the frontend origin.

Browser verification uses intercepted responses to check UI routing, payloads, error handling, and rendering. Those checks do not certify backend logic or live API behavior. No backend API is marked verified in Miro by those checks.
